**Бүртгэл болон админ самбарын шинэчлэлт: [UPGRADE-v1.3.md](UPGRADE-v1.3.md). GitHub-д оруулах: [GITHUB.md](GITHUB.md).**

**v1.2 шинэ боломж, төлбөрийн migration, өдөр тутмын шифрлэсэн SSH нөөц болон хоосон `/var/handari` хавтаснаас эхлэх заавар: [UPGRADE-v1.2.md](UPGRADE-v1.2.md).**

Хандарь ХХК | Handari Brand-ийн найзын сүлжээ, борлуулалт, бүтээгдэхүүн, бараа материал, тайлан удирдах апп. **Firebase хэрэглэхгүй. Node.js 24.14+ болон SQLite** ашиглана. npm package dependency суулгах шаардлагагүй.

## Windows дээр нээх

Энэ хавтас дахь **start-handari.cmd** файлыг давхар дарж нээнэ. Анх удаа имэйл, нэр, 12–256 тэмдэгттэй нууц үг асууж админ үүсгэнэ. Нууц үг бичихэд дэлгэц дээр тэмдэгт харагдахгүй нь хэвийн. Сервер асмагц **http://127.0.0.1:3100** нээж нэвтэрнэ. Терминалаа нээлттэй байлгана; зогсоох бол Ctrl+C.

PowerShell-оос ажиллуулах өөр арга — **энэ дарааллаар, нэг нэгээр**:

```powershell
cd C:\Users\Awesome\Desktop\HANDARI_v1.0
npm run admin
npm start
```

Админ бүртгэлээ үүсгэсэн бол дараагийн удаа зөвхөн `npm start`. `cd` эхэлж ажиллах ёстой; `system32` дотроос npm ажиллуулахгүй. **Live Server эсвэл public/index.html-ийг шууд нээхгүй**: нэвтрэлт, хадгалалт Node сервер шаарддаг. Root index.html нь эхлүүлэх заавар л харуулна.

## Эхний бүртгэл

1. Бүтээгдэхүүн → Бүтээгдэхүүн нэмэх: бодит нэр, ангилал, код, үнэ, HTTPS зургийн холбоос.
2. Бараа материал → Хүлээн авах: тоо, худалдан авсан нэгжийн өртөг, баримтын дугаар/шалтгаан.
3. Найзууд → Шинэ найз: нэр, төрөл, утас, урьсан найз. Жагсаалт / Сүлжээний мод сонгоно.
4. Борлуулалт → Бүтээгдэхүүн, тоо, үнэ, худалдан авагч, төлбөр, зардлаа оруулна. Өртөг, ашиг автоматаар тооцогдоно.
5. Тайлан → Өдөр, долоо хоног, сар, жил эсвэл дурын хугацаа. CSV нь Excel-д UTF-8 BOM-тай нээгдэнэ.

Хуурамч бүтээгдэхүүн, үнэ, статистик суулгаагүй. Нэвтрээгүй эсвэл өгөгдөл ачаалагдаагүй үед «—» харагдана. Хоосон сан руу нэвтэрсний дараа 0 гэж харагдах нь бодит хоосон сангийн тооцоо.

## Хуучин эх файл ба мэдээлэл

`legacy/` дотор анхны зургаан файл **өөрчлөлтгүй** хадгалагдсан. `firebase.js`, `firestore.rules` нь зөвхөн хуучин хувилбарын архив; шинэ апп тэднийг ачаалахгүй. Шинэ сервер зөвхөн `public/` доторх зөвшөөрөгдсөн файлуудыг үйлчилнэ. `legacy/`, SQLite болон серверийн код вебээр нээгдэхгүй.

Бодит хэрэглэгчийн Firestore өгөгдлийг энэ ажилд татаж аваагүй, Firebase нэвтрэлтийг туршаагүй. Эх хувилбар найз, борлуулалтыг `users/{uid}/private/friends` болон `sales` документын `items` массивт хадгалдаг. Хуучин Google/Email дансны нэвтрэлт шинэ серверийн данс руу автоматаар шилжихгүй; шинэ админ нууц үг үүсгэнэ.

Мэдээллээ шилжүүлэхдээ эхлээд Firestore export/backup авна. Дараа нь өөрийн дансны хоёр `items` массивыг доорх бүтэцтэй JSON файлд оруулна:

```json
{
  "friends": [
    {"id": 1, "parent": null, "name": "ӨӨРИЙН БОДИТ НЭР", "type": "Хөгжүүлэгч найз"},
    {"id": 2, "parent": 1, "name": "ӨӨРИЙН БОДИТ НЭР", "type": "Хэрэглэгч найз"}
  ],
  "sales": [
    {"name": "ӨӨРИЙН БОДИТ БАРАА", "qty": 1, "price": 0, "cost": 0}
  ]
}
```

Дээрх нь бүтэц тайлбарлах жишээ; бодит массивуудаар солино. Нэг массив хоосон бол `[]` байна. Нийт 1000 хүртэл бүртгэл, 900 KB хүртэл файл. Апп → Миний булан → JSON файл импортлох → тоог шалгаад батална.

- Найзуудын parent холбоосыг шинэ дугаарт хөрвүүлж сүлжээний модыг хадгална.
- Хуучин найзын утас, бүртгэлийн огноо эх өгөгдөлд байхгүй. Утас хоосон, бүртгэлийн огноо **импортын огноо** болж, тэмдэглэлд тодорхой бичигдэнэ.
- Огноо, барааны холбоосгүй хуучин борлуулалтыг **Борлуулалт → Хуучин хувилбарын архив** хэсэгт хадгална. Тэдгээр нь шинэ орлого/ашгийн хугацаат тайлан, үлдэгдэлд нөлөөлөхгүй. Огноо эсвэл бараа зохиохгүй.
- Импорт бүхэлдээ transaction: нэг мөр буруу бол бүх импорт буцна. Байхгүй parent, тойрог холбоос, давхардсан id-г хаана. Ижил агуулгатай файлыг дахин импортлохгүй. Хэсэгчлэн давхцах өөр файлуудыг автоматаар нэгтгэхгүй; нэг эх export-оо нэг удаа импортолно.
- `legacy/` дахь файлууд нь Cloud Firestore өгөгдлийн нөөц биш. Хуучин өгөгдлийг баталгаажуултал Firebase төслөө бүү устга.

## Тооцоолол

- Борлуулалт, нөөц, барааны хөдөлгөөн, audit, operationId нэг SQLite transaction-д хадгалагдана. Давхар товшилт, ижил хүсэлт үлдэгдлийг дахин өөрчлөхгүй.
- Нөөц хүрэлцэхгүй үед борлуулалт хадгалагдахгүй. Хүлээн авалтад жигнэсэн дундаж өртөг тооцно.
- Борлуулах үеийн нэр, үнэ, өртөг snapshot болж хадгалагдана. Дараа нь бүтээгдэхүүн засахад хуучин тайлан өөрчлөгдөхгүй.
- Цуцлахад хуучин өртгөөр нөөц буцна; борлуулалтын дүн өөрийн анхны огнооны тайлангаас хасагдана. Нягтлан бодох хаалттай хугацааны журнал биш.
- Нийт ашиг = баталгаажсан борлуулалтын орлого − борлуулсан барааны өртөг − борлуулалттай холбоотой зардал − бусад зарлага. Бараа худалдан авалтын өртгийг давхар «бусад зарлага» болгож бүү бүртгэ.
- Касс, банкны бодит үлдэгдэл, татварын тайлан тооцохгүй. Авлага, төлбөрийг тусдаа хэсэгт бүртгэнэ. Ашгийг бэлэн мөнгөний үлдэгдэл гэж үзүүлэхгүй.
- Тооллогын утга шинэ бодит үлдэгдэл болно. Шалтгааныг заавал оруулна. Бүх хөдөлгөөн түүхтэй.
- Бүтээгдэхүүнийг архивлаж түүхийг хадгална. Хүүхэд холбоостой найзыг устгахаас өмнө холбоосуудыг шилжүүлнэ. Найз устсан ч өмнөх борлуулалтын snapshot үлдэнэ.
- Мөнгийг дотооддоо JavaScript number-оор хадгалж, төгрөгөөр бүхэлчилж харуулна. Дундаж өртөг бутархай байж болно.

## Нэвтрэлт, эрх, нууц үг

Нууц үгийг scrypt hash-тай, session token-ийг зөвхөн SHA-256 hash-аар санд хадгална. Session 7 хоног хүчинтэй; cookie нь HttpOnly, SameSite=Strict, HTTPS үед Secure. POST хүсэлтэд Origin таарах шаардлагатай. Нэвтрэлтийн оролдлого IP бүрт 15 минутанд 15; Node restart хийхэд тоолуур цэвэрлэгдэнэ.

Анхны админыг серверийн `scripts/admin.mjs` үүсгэнэ. Хэрэглэгч өөрөө бүртгүүлж, админ зөвшөөрсний дараа нэвтэрнэ. Админ самбараас хэрэглэгчийн эрх, төлөв, найзын холбоосыг удирдана. Гишүүд зөвхөн нийтэлсэн каталог болон өөрийн холбоотой худалдан авалтыг харна. Өөрийгөө админ болгох боломжгүй. Google OAuth, SMTP нууц үг сэргээх, имэйл баталгаажуулалт, баталгаат урилга ороогүй.

Нууц үгээ мартвал **серверийн эзэмшигч** `npm run admin`-аар ижил имэйлээ оруулж `RESET` батална. Энэ нь админ эрх олгож, хуучин session-уудыг хүчингүй болгоно. Энгийн нууц үг солих бол Миний булан → Нууц үг солих; бүх session хүчингүй болно.

## Ubuntu серверт байрлуулах

Энэ ажилд бодит Ubuntu серверт холбогдож байрлуулаагүй. Дараах командуудыг сервер дээр ажиллуулна. Домэйны DNS A/AAAA бичлэгийг сервер рүү чиглүүлнэ. Node.js **24.14+ LTS** суулгаж `node --version`, `command -v node` шалгана. systemd service-ийн `/usr/bin/node` зам бодит суулгалттай таарч байх ёстой; root-ийн nvm зам хэрэглэхгүй.

```sh
sudo apt update
sudo apt install nginx certbot python3-certbot-nginx
sudo useradd --system --home-dir /var/lib/handari --shell /usr/sbin/nologin handari
sudo install -d -o root -g root -m 755 /var/handari
sudo install -d -o handari -g handari -m 700 /var/lib/handari
```

Төслийн кодыг `/var/handari` руу хуулна. `data`, `backups`, `.qa`, `.git`-ийг хуулахгүй. Код root эзэмшилтэй, үйлчилгээ унших боломжтой байна.

`deploy/handari.service`, `deploy/nginx.conf` доторх **handari.example.com**-ийг бодит домэйноор солино. `APP_ORIGIN` нь `https://таны-домэйн` хэлбэртэй, төгсгөлд `/` байхгүй байна. Домэйн, схем, порт яг таараагүй бол нэвтрэлт, хадгалалт 403-аар хаагдана.

```sh
cd /var/handari
sudo -u handari env DB_PATH=/var/lib/handari/handari.sqlite /usr/bin/node scripts/admin.mjs
sudo cp deploy/handari.service /etc/systemd/system/handari.service
sudo cp deploy/nginx.conf /etc/nginx/sites-available/handari
sudo ln -s /etc/nginx/sites-available/handari /etc/nginx/sites-enabled/handari
sudo nginx -t
sudo systemctl daemon-reload
sudo systemctl enable --now handari
sudo systemctl reload nginx
sudo certbot --nginx -d handari.example.com
```

Certbot командын домэйныг мөн солино. HTTP → HTTPS redirect сонгож, HTTPS бэлэн болсны дараа нэвтрэлтийг туршина. Firewall дээр SSH-ийн одоогийн портоо хадгалж 80/443 нээнэ. 3100 портыг нийтэд нээхгүй; Node loopback дээр сонсоно. `TRUST_PROXY=1` зөвхөн энэ Nginx тохиргоотой хэрэглэнэ.

```sh
sudo systemctl status handari
sudo journalctl -u handari -n 80 --no-pager
sudo certbot renew --dry-run
```

## Нөөцлөх ба сэргээх

Online backup API нь WAL ажиллаж байхад тууштай нөөц үүсгэнэ. Ажиллаж байгаа `.sqlite` файлыг дангаар нь шууд хуулж нөөцлөхгүй.

Локал: `npm run backup` → backups/ хавтас. Production дээр гаралтын зам **заавал** өгнө:

```sh
sudo install -d -o handari -g handari -m 700 /var/backups/handari
sudo -u handari env DB_PATH=/var/lib/handari/handari.sqlite /usr/bin/node /var/handari/scripts/backup.mjs /var/backups/handari/manual-2026-11-04.sqlite
```

Нөөц бүрт шинэ нэр өгнө; ижил файлыг дарж бичихгүй. Өдөр тутмын cron/systemd timer, өөр төхөөрөмж рүү шифрлэсэн хуулбар тохируулна. Нөөц нь хувийн мэдээлэл, нууц үгийн hash агуулна; нийтэд байрлуулахгүй. CSV бүрэн нөөц биш.

Сэргээхдээ үйлчилгээг зогсоож одоогийн сан болон `-wal`, `-shm` файлуудыг тусдаа rollback хавтас руу хамтад нь хадгална. Сонгосон backup-ийн `PRAGMA integrity_check` нь `ok` эсэхийг шалгана. Нөөцийг `/var/lib/handari/handari.sqlite` болгон хуулж `handari:handari`, `0600` эрх олгоно. Хуучин WAL/SHM-ийг шинэ сантай үлдээхгүй. Үйлчилгээг асааж найз, нөөц, борлуулалтыг шалгана.

## Android PWA

HTTPS хаягийг Chrome-оор нээх → цэс → Нүүр дэлгэцэд нэмэх / Апп суулгах. Manifest, 192/512 PNG, service worker орсон. Service worker нь зөвхөн нийтэд нээлттэй аппын бүрхүүлийг кэшлэнэ; API болон хувийн мэдээллийг кэшлэхгүй. Гарахад UI өгөгдөл цэвэрлэгдэнэ. Офлайн үед серверийн үйлдэл ажиллахгүй. Шинэ release-д `public/sw.js` дахь CACHE хувилбарыг нэмнэ; шинэчлэх мэдэгдэл гарна.

## Шалгалт

```sh
npm test
```

10 автомат тест: API нэвтрэлт/эрх/Origin, stock transaction/idempotency/rollback, найзын мод/импорт, backup/restore integrity. Chrome headless QA: найз нэмэх/засах/мод, бүтээгдэхүүн, хүлээн авалт, борлуулалт, зарлага, тайлан, QR зураг, цуцлалт, гарах; 390px дэлгэц дээр бүх хуудас overflow-гүй. Бодит өгөгдөл, хэрэглэгч үүсгэхгүй; QA сан зөвхөн санах ойд.

`npm run qa` нь өмнө суусан Chrome шаарддаг. Windows бус орчинд `CHROME_PATH` өгнө. Скриншот `.qa/` дотор. Энэ шалгалт нь бодит Samsung Android дээрх суулгалт, production HTTPS, SMTP/Google OAuth болон бодит серверийн deployment-ийг батлахгүй.

Өдөр тутмын жижиг багт зориулсан нэг Node process / нэг SQLite сан. Олон сервертэй deployment хэрэгтэй бол PostgreSQL, хуваалцсан session/rate-limit рүү шилжүүлнэ. PDF export, татварын нягтлан бодох бүртгэл энэ хувилбарт ороогүй.
